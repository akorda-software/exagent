## Decisión, autorización y fuentes

- ReqLLM estable actual consultado en Context7 `/agentjido/req_llm` y API Hex:
  **1.24.0**, requisito `~>1.24.0` para acotar patches inicialmente. Código final
  leído en `deps/req_llm`; `lib/req_llm.ex` coincide byte a byte con el checkout
  de referencia `fd9e079fddf253e9b719b2d2c6920f4306592809`.
- ADR en diseño8.15: una interacción pública, ExAgent posee loop/tools/autoridad,
  persistencia/continuación y validación final. No parser privado ni fork; no
  callbacks ReqLLM usados para ejecutar efectos del framework.
- **Cambio mínimo autorizado:** `llm_db >=2026.9.3` obligatorio exige Elixir1.18
  (confirmado metadata Hex2026.9.3 y fuente2026.9.4). Coordinador autoriza
  `~>1.18`, migración/CI/docs coherentes y evaluación1.18/28 y1.20/29; sustituye
  la decisión provisional de mantener1.17 pendiente por toolchain ausente.
  No se cambió el mínimo para ocultar warnings ni se fingió soporte1.17/OTP27.
- ReqLLM inicia supervisor/Finch y carga `.env` por defecto: impacto público
  documentado. `config/test.exs` y consumidores usan `load_dotenv: false`;
  los hosts resuelven esa configuración antes del arranque, sin mutación global.

Fuentes: [release ReqLLM](https://hex.pm/api/packages/req_llm/releases/1.24.0),

## Fallos y fronteras comprobadas

- **Fixture incorrecta:** `Context.new/1` recibe lista de mensajes, no prompt.
  Cambiado a API pública `Context.normalize/1`, tras reproducir Protocol.UndefinedError.
- **Supuesto de integración incorrecto:** `req_http_options.retry:false` se
  sobrescribe al adjuntar Retry de ReqLLM; error429 hizo nuevas requests. Añadir
  `max_retries:0` público da una sola invocación observable. Regresión permanente.
- **ExDoc:** instalar ReqLLM hizo resoluble la referencia previa al módulo oculto
  ReqLLM.Usage.Normalize; se sustituyó por ruta de fuente, conservando el hallazgo
  sin autoenlace a API privada. Log rojo y corregido separados.
- **Aislamiento de probe:** `documentation_probe.exs` usa Elixir directo y no
  carga config/test; primera ejecución pudo cargar `.env` por el default de la
  nueva dependencia. No se inspeccionaron valores ni ejecutaron llamadas live.
  Se añadió `load_dotenv:false` antes de startup sólo en la VM disposable y se
  repitió la probe; config/test no protege procesos Elixir directos.
- APIs verificadas: spec explícita fuera de catálogo, auth/base URL por instancia,
  request real codificada/response decodificada, `Response.classify/usage/output_items/
  call_metadata/tool_calls`, IDs/args exactos, `Context.append_tool_exchange/3`,
  rechazo de resultado tool faltante, cero efectos y cero follow-up automático.
- **R1.5: gap reproducido:** `usage` ausente, parcial sólo `completion_tokens:2`
  y cero explícito producen input/output/total0 tanto en `Response.usage/1` como
  `call_metadata/1`; metadata pública observada sólo añade `api_type`. La probe
  no acepta esta pérdida como contrato ExAgent, ni reconstruye con parser privado.
  R1.5 debe hallar extensión pública fiel o bloqueo explícito; no inferir desde cero.
- `stream_text/3`, vista única `StreamResponse.events/1` y `close/1` inspeccionados
  en contrato/fuente. Streaming no ejercitado por estas tres pruebas: lazy/cleanup,
  presión y bytes siguen R1.4; firmas/metadatos multi-turn R1.3.

## Advisory real separado de warnings

Hex informó **CVE-2026-82672 / GHSA-rj5m-69wp-cxq9** sobre Mint1.10.0 ya presente
en R0. [Fuente oficial CNA](https://cna.erlef.org/cves/CVE-2026-82672.html):
afecta versiones `<1.10.1`, corregido en1.10.1. Cola de respuestas HTTP1 puede
desincronizarse con origen controlado por atacante + intermediario estricto +
conexiones reutilizadas. Es relevante al aislamiento de respuestas del framework
en esa topología; no se demostró explotación de este host ni cubre ese riesgo la
suite offline. No es sólo un warning de compilador.

Propuesta mínima comunicada: elevar floor Mint a1.10.1, actualizar sólo Mint y
probar framing HTTP1 mediante fixture discriminante. Queda seguimiento separado:
se preservó el floor/lock raíz solicitado. Los consumidores nuevos resolvieron
1.10.1 naturalmente, lo que no corrige consumidores fijados a1.10.0.
