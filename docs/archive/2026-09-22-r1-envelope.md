## Criterios previos y resultado

Antes de levantar el guard de un perfil: ReqLLM real generate_text y una vista
process_stream, transporte JSON sintético y SSE loopback. Negativos `[]`, `[{}]`,
null/string/number/boolean, `{}`, sobre truncado/missing/extra, arguments array/null:
cero efectos; vacío y no vacío válidos: exactamente uno e ID call-gate conservado.
Después de seguimiento, function.arguments se divide por codepoint entre múltiples
deltas, incluidos positivos y truncación; no se afirma fragmentación TCP/UTF8
arbitraria. Sólo process_stream enumera y el metadata handle termina. El gate9/9
es distinto de la integración public Model/ExAgent.run y no habilita request_stream.

Perfil aceptado offline: `tool_profile: :chat_tools_v1`, spec OpenAI explícito
id `envelope-fixture`/`envelope-gate`, `extra.wire.protocol=openai_chat`, tools enabled,
reasoning disabled, no tools.strict=true ni provider options adicionales. Gateway
sintético `https://fixture.invalid/v1` con transporte inyectado; SSE/HTTP real sólo
`127.0.0.1`/puerto efímero con cleanup. Ruta observada `/v1/chat/completions`;
Responses/no wire metadata/Google/reasoning/strict rechazan antes de IO. No catálogo
ni configuración sintética constituye modelo live aceptado.

ReqLLM.Tool strict:false omite campo wire strict; se exige esa ausencia y schema
efectivo íntegro. No se inserta optional en required ni default en args. Helper
provider-agnostic/versionado usa Tool/JSV existente, callbacks upstream noop y
json_repair:false/max_retries:0 protegidos. Subset explicitado en diseño8.23:
root object/boolean, anidados/arrays/enums/null/defaults inertes y posiciones schema
conocidas; refs/$defs/id/anchors/dynamic/dialect/keywords no representables rechazan
preIO sin fetch ni rewriter. Ecto embeds inline funciona sin refs.

Integración comprueba IDs/orden/texto/resultados, argumentos lógicos en hooks/DI,
revalidación efectiva, rechazo de cambio ID/nombre/metadata del perfil, deny/ask,
approval callback con args efectivos y ancestro que permite delegate pero deniega
effect. No se implementa aprobación durable. Ecto final_result vacío/embed/null
acepta; cambio que el changeset rechaza provoca un retry correctivo y dos requests,
sin output nativo. JSON/Server snapshot/restore/compaction preservan continuation2,
codec exagent.arguments/1, historia canónica y outcomes sin replay. Call history
sin codec/mapa válido rechaza, no se legitima envolviéndola.
